## Why

The generated plan is written once and then only changes when the user moves something. Real weeks do not go to plan: a session is skipped, a run goes much longer, the knee hurts, the night was bad, Garmin revises the threshold. `BRAINSTORM-miglioramenti-e-gamification.md` §0.4: adaptation starts from precise events, not a nightly rewrite; by default it is automatic with a notice at levels 1–2 and a proposal to accept at level 3, and the user can change that in the settings. Manual edits always win.

## What Changes

- **Event detection**, deterministic, from stored data: pain reported (today or yesterday), a session reported `troppo` or a body reported `stanco`, today's readiness `scarico`, a planned session skipped or done at under 50% or over 150% of its planned minutes in the last 3 days, and a change of the Garmin threshold since the plan was generated. Each event is handled once.
- **Two responses**, both inside the code's limits:
  - *soften* (instant): the next hard sessions in the affected days become their easy version (`move_check.adapt`), for pain the next 2 days, for tiredness, `troppo` or low readiness the next day with a hard session;
  - *replan*: the window from tomorrow is regenerated by the plan generator (model, checks, fallback), with the soften rules applied on top when both are due.
- **Mode**: `automatico` applies the change and shows it on Oggi with an undo; `proposta` shows it with Accetta / Rifiuta. Sessions the user edited are never touched; a conflict with one is reported.
- **Settings**: the level screen gets the mode switch (automatic, proposal, or the level's default).
- API: `POST /plan/adaptation/check`, `GET /plan/adaptation`, `POST /plan/adaptation/{id}/accept|reject|undo`.
